# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Yorimichi (寄り道) is a small top-down Japan travel-journal game prototype: Phaser 3 + TypeScript + Vite, with no external assets and no backend. `AGENTS.md` holds the repository guidelines (style, commits, PRs). Follow it as well.

## Commands

- `npm ci`: install (Node.js 22.12+).
- `npm run dev`: Vite dev server (binds `0.0.0.0`).
- `npm run build`: `tsc --noEmit` then `vite build` to `dist/`. This is the only automated check: there are no tests, linter, or formatter.
- `npm run preview`: serve `dist/`.
- `node scripts/subset-pixel-font.mjs <DotGothic16-Regular.ttf | PixelMplus10-Regular.ttf>`: regenerates `src/fonts/<font>-subset.woff2` from every character in `src/`: DotGothic16 is the kiosk's pixel font, PixelMplus10 the map signs' bitmap font. Re-run both after adding Japanese text; missing glyphs fall back to Noto Sans JP.
- `[YORIMICHI_CODE=…] node scripts/import-photos.mjs <selection folder>`: fills `local-photos/` plain (read by the dev server only, through the `vite.config.mjs` middleware; `photoBase` in `access.ts`) and, with the code, `public/photos/` encrypted, each with its `index.json`, resized and stripped of metadata, GPS included; both git-ignored (personal photos in a public repository). Its `pages` maps the selection's folders to album pages. In production the photos are not in the image: they live on the VPS in `/srv/yorimichi/photos` (the encrypted `public/photos/`, `index.json` included), mounted read-only on `/usr/share/nginx/html/photos`, so that personal photos stay out of the public repository and the registry. The image does hold `public/access.json`, the title's code verifier (`Dockerfile`).
- `node scripts/make-icons.mjs`: redraws the home-screen icons `public/icon-192.png` and `public/icon-512.png` (a torii, 16×16 pixel art) named by `public/manifest.webmanifest`; the `Dockerfile` copies the three into the image.
- `npm run build:mobile`: build, then `scripts/export-mobile.mjs` inlines the bundled JS and CSS into `dist/yorimichi-mobile.html` (optional output path argument: `node scripts/export-mobile.mjs <path>`). The script finds assets by regex-matching Vite's `<script type="module" crossorigin src=…>` and `<link rel="stylesheet" crossorigin href=…>` tags, so a change to how `index.html` loads assets can break it.

Verification is manual in the browser: movement (tap-to-walk and arrow keys), interaction prompts, ticket purchase and cancellation, platform validation, return trips, and the souvenir journal. For kiosk changes, check both the Japanese and English screens and that Escape closes the kiosk.

## Architecture

- **`src/main.ts`**: a single Phaser scene, `Journey`, on a fixed 960×640 canvas. `loadPlace(place)` tears down and rebuilds everything per location: the world container, HUD, collision rectangles (`solids`), commuters, and player. Interaction hotspots in `nearby()` and the collision rectangles are **hardcoded pixel coordinates** that must line up with what `art.ts` draws. Tap-to-walk uses a BFS over a 16px grid (`navigate`). In-game dialogs are Phaser containers stored in `this.modal`. Any non-null `modal` suspends movement and interaction.
- **`src/title.ts`**: the title screen before the game starts (`showTitle`, then `main.ts` creates the `Phaser.Game`): one 320×200 pixel-art picture (`backdrop`, `train`, scaled by `fitPicture`, lettering through `crispText`/`write`) in phases (`Phase`): the journal check (production builds only: in dev it opens on the menu; `unlock` in `access.ts`, typed into an invisible `<input>` laid over the drawn box so phones get a keyboard), the main menu (continue / new journey), the erase confirmation, and the traveller's looks. Items (`Item`) are worked by pointer, arrows / WASD, pad (`connectedPad`), Esc / B back. **`src/look.ts`**: the traveller's `Look` (`parts`, each an index into its choices), saved under `yorimichi-look` by Begin (after `eraseAll`), and `paintTraveller`, the 20×28 frame `makeArt` paints the `traveller-<dir>-<frame>` textures with: every look stays inside that frame, so sprite size and origin never change; a costume (`outfit` other than casual) ignores the jacket and trousers (`unused`), the astronaut's helmet and the dinosaur's hood replace the hat. A part added later is read from an older saved look as its first choice.
- **`src/art.ts`**: all visuals are drawn procedurally into 480×320 canvas textures (`map-<place>`, `traveller-<dir>-<frame>`, `commuter-<look>-<dir>-<frame>`) and shown at 2× with `pixelArt: true`. So art coordinates × 2 = scene coordinates. The map and exit-pillar canvases are allocated at twice that size and drawn in art coordinates (`mapCanvas`), so their lettering (`letter`) can use the PixelMplus10 bitmap font, whose outlines are whole pixels: 10px small print (5 art px per line, half an art px per dot) or `big` at 20px (10 art px, a dot per art px). Kanji and kana are as wide as the line is high, Latin half that, and the signs are sized around it. Other sizes would blur the dots. The game only starts once that font is loaded; at the hubs the world container sits 24px lower (`this.world.y`) so the back wall has room for the station's name, and pointer and prompt positions convert through it. The gate signs show their tracks from `tracksFor()`. The hub map mirrors the first-person hall's layout (machine wall at the back, ticket office then central gates on the left, Shinkansen transfer gates on the right, or a NewDays where `hasShinkansen(hub)` is false); keep the two views consistent when either changes. The art-px landmarks are listed above `makeHub`, which draws a station's map (`map-<hub>`) and exit pillars the first time it is visited; the station's name plate grows to hold a long name. The board above the machines is a little fare map, of its region (`onTokyoBoard`, or the Kyoto side); the halls (`hall-picture.ts`, `hall-scene.ts`, `hall-voxels.ts`) show the SVG. Stations `inKyoto` (`network.ts`) keep the layout, hotspots and solids of the others but are dressed in timber, plaster, tile and stone: `makeHub`, `exitPillar`, `makeTown` (`kyoto` flag; `tower`, Kyoto Tower, at Kyoto Station), `HallPicture.paint`, the posters (`hallPosters`) and the lit lattices in `main.ts`. The three.js and voxel halls only take the posters and exit names.
- **`src/palette.ts`**: the scene's colour grade (`vivid`, a post pipeline on the main camera, WebGL only): muted greens and olives shown as a fresh grass green, beiges and creams with less yellow, olive greys cooled to blue-grey, vivid colours left as drawn. The art's hex colours are what goes in, not what is seen; the DOM overlays (hall, gate, kiosk) are not graded.
- **`src/people.ts`**: the commuters' outfits (`looks`), shared by the hall's sprites (`hall-scene.ts`) and the top-down commuters (`art.ts`, animated in `main.ts`), so the same people appear in both views. `Figure` is a commuter as the concourse simulation in `main.ts` has them; the hall shows those figures live (the simulation keeps running under it), placed through `fromConcourse` in `hall-scene.ts`, a piecewise mapping of top-down scene pixels onto hall units anchored on landmarks both views share (office counters, gate lanes, the bank's pillars and machines, the Shinkansen gate lanes or the shop door, the exit pillars; `anchors(shinkansen)`). Moving any of these in either view means updating its anchors. The machine the player stands at (in front of it in the hall, or before it on the map) is `playerSpot`: commuters never pick it and those on the way there turn to another (`giveWay`); one already using it finishes first, and meanwhile the hall refuses it (`busy`). On the map, player and commuters jostle instead of colliding: contact slows both for a moment (`bump`) and nudges a walking player aside, one distance check per commuter.
- **`src/crowd.ts`**: how many people are about: each `Stage` (concourse, corridor, platform, `town`, `home-street`) has its peak, a station its share of it (`tiers`, roughly its daily passengers; unlisted: suburban) and the hour its part of that (`hours`: `work`, `leisure` or `night`, by `days`). `Journey.gather` creates the place's most (`busiest`), outfits repeating past the last only among the plain ones; `planTrip` keeps anyone past `crowdAt` out of sight, so the crowd follows the clock without a reload, and `alight` lets as many off as the crowd warrants. The street's passers-by run `streetTrip` (ends of either pavement, station entrance while open, konbini door, over the crossing between pavements, stops at the bus stop where there is one, vending machines, area map), the lane's `laneTrip`. The 3D and voxel halls hold one model per outfit, so they show a repeated outfit only once.
- **`src/clock.ts`**: the journey's own clock (game ms, Japan time read through the UTC fields), `speed` × real time, advanced by `tick()` in `Journey.update` by the real time elapsed (`performance.now()`, not Phaser's delta, which stops in a hidden tab and is capped in a throttled one), so it runs under every overlay and in the background and saved as `clock` in the save; `?time=HH:MM` sets it at load, and `debugTime` (T, or a click on the HUD's clock) at any time through `setTimeOfDay`, retiming the platform's trains. The HUD's top band is one picture, `paintHud` in `art.ts` (`hudLayout`, in art px: the clock's card, top left, a click on it `debugTime`, the needs' inset, the purse, the Menu, Bag and Journal buttons; repainted by `refreshHud` when what it shows changes, kept up in `update`), the needs' bars and icons laid over it; `clockBadge()` (a DOM clock that follows it) is unused since the first-person views lost their headers. The stations open from `opens` to `closes`, trains are due from `firstTrain` to `lastTrain` (`trainsRun`, `inService`). On a platform a `Train`'s `due` is its departure in absolute game minutes: it pulls in `dwell` ms before it and never closes its doors earlier (`dueIn`); when the clock has run on without the scene (another tab or window), `runTrains` moves a late train's `due` on to the earliest it can still leave, with a minute's leeway; riding moves the clock on (`ride`: `localMinutes`, `shinkansenMinutes` in `fares.ts`). Night (`darkness`): out of doors (`outdoors()`), `Journey.shade`, a MULTIPLY render texture above the world, is filled dark blue and lightened by `lamps()` (scene px, matching `art.ts`); on platforms it is filled evenly at .4 strength, without lamps; what glows by itself (`neon`: lit windows, shop signs) and, out of doors, the hotspot outlines sit in `over` above it; the HUD is at depth 10. Past `closes`, `shutter` rolls down (`rollShutters`; at once on arriving) over the concourse's gates, office, machines and shop, `nearby()` leaves only its exits (it stays a way through, for commuters too) and `closeStation()` sees the traveller from behind the gates back to it (not while on a train). Overlays already open there finish normally.
- **`src/rail.ts`**: the JR network as data, the single source of truth for lines: `railLines`, each with its colour, service and **ordered stops** (Japanese names; real lines and stopping orders, keeping only the stations the game knows; a rapid service simply omits the stations it skips; `loop` for the Yamanote Line). Its order is also the side-by-side order of lines on the fare map. `stopNames` gives every stop's English name (a stop without one throws at load), `linesAt(station)` gives the lines through a station, `firstLegs(from, to)` the lines to start on to reach `to` with the fewest changes (what a fare ticket's platform must be). `connectionsAt(station, on)` is what the platform's maps (`lineMap`, `routeMap`, `loopRing`) show as icons under a stop's name (`lineTag`): the other lines there, by their symbol (`marks`), then the `busLines`, Kyoto's city buses to Kinkaku-ji and Ginkaku-ji, connections only for now: no stations, no fares, not rideable (`busLegend` says where they go).
- **`src/network.ts`**: the single source of truth for places, stations, Shinkansen routes and platform numbers. Every stop of a local line of `rail.ts` is a station (`stations`, by id: its English name in kebab case, `stationAt(ja)`), all with the same concourse, corridor and platforms; `known` holds what sets a few apart (exit names, Tokyo's and Kyoto's track numbers, `maps` for an exit with its own map: Kamakura's east exit to `kamakura-trail`, Saga-Arashiyama's to `arashiyama`, `stationOf` the way back). Two lines that are not JR, the Karasuma subway and the Keihan, are ordinary local lines of `rail.ts`, as Kyoto's other stops (fares by the same bands, changes free at Kyoto and Tofukuji). Kyoto's Jujo is the stop `'十条\u200b'` (a zero-width space, invisible on the signs), id `jujo-kyoto`, English `Jujo`: stops are keyed by name and Tokyo has its own 十条. Every other exit leads to the generic street `town`, drawn per station and exit on first use by `makeTown` in `art.ts`, its sign naming them (its area map, read up close, by `makeAreaMap`); `Journey.outside` remembers where the player came out, to walk back in there. A station without a Shinkansen platform gets the shop instead of the transfer gates and a local machine in place of the Shinkansen one (`machineKinds`). `tracks` numbers the two tracks of every line through a station (generated by `numberTracks` where `known` gives none: a pair per line, lines of one colour sharing it); `platformsAt(hub, service)` groups them into the platforms behind the gates (lines sharing a pair share one), and `tracksFor` gives the range shown on the gate signs, the gate's board and by the station staff (`駅員`). `routes` are the Shinkansen tickets, generated between every two stations of a Shinkansen line (`lineId`, from which they take their names and colour), from the track running the destination's way, priced by `shinkansenFare`; local trips are fare tickets. `exits` names a station's exits where they are not 西口 / 東口 (`exitName`: Kyoto's 烏丸口 and 八条口). A second rental, `kyotoHome` (Jujo's west exit), has the same sign in its `town` (`laneText`), leading to `kyoto-lane` (`makeKyotoLane`, one screen, the little house after the traveller's photos: owl noren, charred lattices, five outdoor units; around it the low town: hills, utility poles, the bend (`laneInner`, `laneOuter`, the latter shared with its solids) up to the back street, the way to the station, past the car park and the FamilyMart beside it (its `konbini` hotspot opens the shop), a Jizo shrine, the neighbours' roofs and gardens; `laneWindows` lit at night), whose door opens `kyoto-house`; Lorenzo's Uber drives to whichever home is on its side of the country. The traveller's home is `home` (Higashi-Nakano's west exit): that station's `town` gets a `lane` hotspot (the 東中野一丁目 sign drawn by `makeTown`'s `lane` flag) to `home-street` (`makeHomeStreet`, `homeStreetWidth` art px wide, scrolling sideways like the platform, drawn mirrored so that it starts on the right, where the street's left edge leads (lettering excepted, `homeLights`), its `home` hotspot on door 102), which leads into `apartment` (`makeApartment`, a 1LDK 480×416 art px scrolling vertically; its walls and furniture are `apartmentSolids`, its freestanding furniture `apartmentProps`, depth-sorted with the traveller; the `bed` opens `bedside()` in `main.ts`, the alarm's wheel (`src/alarm.ts`, `wakeWheel`: a canvas texture in the modal, 15-minute steps; saved as `alarm`, 9:00 at first, `wake`), and `sleep()` skips the clock to it); both keep `outside` set, and a new journey starts at Tokyo Station with a welcome `dialog` (`create`). Adding a place usually needs the souvenir count and journal entries in `album` (`main.ts`), its screen in `sight-scenes.ts`, and an exit in `known` leading there.
- **The Kyoto house** (`kyoto-house`, `kyoto-upstairs`, `makeKyotoHouse` in `art.ts`, from the owner's plan): two 480×340 art px maps joined by the stairs (`upstairs`, `downstairs` hotspots), the rooms' layout in the comment above `kyotoSolids`, its slanted walls `bathLeft`, `bathRight`, `washRight`, `landingRight`, `balconyTop`. Each of the three bedrooms' beds (`bedE`, `bedD`, `bedC`) opens the same `bedside()`; its windows are `kyotoWindows`.
- **`src/fares.ts`**: fares as JR computes them: `fareBetween(from, to)` (Japanese names) is the March 2026 JR East band (`fareForKm`) for the shortest operating km along the local lines (Dijkstra over neighbouring stops, km from `fromTokyo` or `fromKyoto`, the real km in `between` where two neighbours are reached from opposite ways round); null between the Tokyo and Kyoto networks. `faresFrom` gives the amounts a station's machines sell. `tokyo-fares.ts` checks at load that it gives back the 30 transcribed fares of the Tokyo board. `shinkansenFare` adds the express charge to the fare for the Shinkansen km, `shinkansenMinutes` the ride's length for the machine's trains.
- **The corridor** (`corridor` place, `Journey.gateway` naming the hub and gates): where a gate's `pass` leads, drawn per hub and gates by `makeCorridor` in `art.ts` (layout in `corridorLayout`, art px). Each platform of `platformsAt` has a staircase on each side with its sign; the hotspots (`stairs<i>L`/`R`, and `return` at the gates) are registered into `hotspotFrames`/`hotspotShapes` when it loads. The world is taller than the screen when there are many lines: `mapHeight` bounds walking and the BFS grid, and `scroll()` moves `this.world.y` to follow the traveller (pointer and prompt positions already convert through it). Commuters walk it too (`corridorTrip`, the concourse's step queues between the stairs and the gate lanes, with the adjustment machine and staffed window as spots); how many walk it comes from `crowd.ts`. Climbing (`climb`) only checks that a ticket is punched, wherever it was, then goes up to the platform: the fare is settled on the way out. The punched ticket is the one that went through, `punched` with the hub whose gate punched it (where its trip began). A platform's stairwell (`descend`) leads back down to the corridor at its stairs (`stairsSpot`), ticket still punched: changing lines is walking to another staircase. The way out is the gate view in exit mode (`exitGate`, `GateSide.exit`: the station's entrance hall drawn beyond, `entrance`; the gate never shows why it refuses), which refuses a ticket punched at the same station; the corridor's staffed window (`window` hotspot: the concourse's ticket office, `ticketOffice` in `art.ts`, drawn again set into the left wall beside the gates; `staffWindow`) cancels that entry and lets the traveller out whatever went wrong (the hook for charging a missing fare later): `fareDue` (`ticket-machine.ts`) checks the trip from the punch to here, and the gate keeps a ticket that covers it and refuses the rest. The fare adjustment machine (`adjust` hotspot in the corridor's last 40 px before the gates, opposite the staffed window; `MachineKind` `'adjust'` of the kiosk, tickets dragged from its wallet panel onto the card slot) swaps a short ticket for an `AdjustTicket` (精算券) once the difference is paid.
- **The Shinkansen** has its timetable (`platform.ts`: a departure each `shinkansenEvery` minutes per track, `onTimetable`, lines sharing a platform taking them in turn, `lineAt`, named by `trainName`), which `dueIn` keeps on a Shinkansen platform and the machine's `train` step lists for the ticket's track. A ticket's `Reservation` holds its day (`date`, `dayOf`; the transfer gates refuse it any other day) and, unless non-reserved (自由席, `nonReserved` less), the train (`due`), car and seat; its cars are numbered from the front (`carAt`, the platform's floor numbers, `reservedCars` those a seat is booked in). Boarding that train by a door of that car sets `seated`, and `ride` then spends nothing and feeds `rested`. It has no corridor: the transfer gates' `pass` goes straight to its ticket's track (`toPlatform`, from the route's `lineId` and `platform`), and a Shinkansen platform's stairwell (`descend`) opens the transfer gates in exit mode (`exitGate`), out to the concourse before them, which cancel an entry made there themselves (`GateSide.cancel`: the ticket comes back out unpunched); its line map offers the stations of its line (those on a local line), and `keep()` saves it as that concourse spot, dropping the ticket of a trip that ended there.
- **The platform** (`platform` place, `Journey.deck`: a `Deck` from `src/platform.ts`, the station, its `Platform` and the track the traveller came up on or arrives on): drawn per station and tracks by `makePlatform` in `art.ts`, `platformWidth` (two screens) long, scrolling sideways like the corridor vertically (`mapWidth`, `scroll()` moves `this.world.x` too; pointer and prompt positions convert through it) (in the street's three-quarter view; layout in art px in its comment: floor 88–232 between the far and near tracks, a stairwell at each end, `downL`/`downR`, the route map board (`routeBoard`, `route` hotspot: `routeMap(track)` shows the face of the side the traveller stands on), the station sign in the middle on its own `<key>-sign` texture (`stationSign`) and the route board on `<key>-route`, sorted with the people at their feet, as is each departure gantry: `platformBoards`, `makeBoard`, a container holding its picture and its two boards' text, `Journey.overhead`), trains by `makeTrain` per line (`trainLayout`, `doorMarks`: the doors line up with the 乗車位置 marks), the same picture on either track, its roof over the side facing us (`trainTop`): the far train shows its doors opening; the near train's are out of sight, its roof biting into the platform's edge up to the white line (sorted at the edge, so that those there pass behind it), and an open one shows as the light spilled over the gap. `runOf(line, station, track)` gives where a track's trains go: the pair's first track towards the start of the line's `stops`, the second towards the end, both the only way at a terminus (so a route's `platform` must be the track running its way). Each track's `Train` cycles in `runTrains` (gap, arrive, alight, board, close, leave; lines sharing the platform take turns); commuters queue at the marks in two lines either side (`queues`, each commuter's place in `queue[2]`: even left, odd right, a row back every two; `slot`, `freeSlot`, `platformTrip`), get off through the middle in `alight` (the `off` step to `clearPoint`; a traveller in their way is shoved aside and dazed, `stun`), then board in `boarding`, the lines taking turns (`served`) while `requeue` moves one line up. The traveller comes up at the end of the corridor stairs' side (`deck.track`) and boards from a queue (`door<track>-<k>` hotspots, outlined on the train's door itself, the glow kept above the people and trains, but not clickable: a click on a standing train picks its nearest door; `queueEnd`, `boardAt` boards on their own when nobody is ahead or getting off there, from the doors' opening, `boardable`) and rides (`modal` set, hidden): on boarding, the doors held open, `lineMap` offers the stops `alightAt` knows (every station), and on a loop (`loopRing`) the ring, also on the route map; the choice (`train.to`) shuts the doors at once and, once the train has left, `toPlatform(train.to)` lands them on that station's platform as the train pulls in (`arriving`); staying steps back off by the same door (`stepOff`; `stayed`, the track of a train just stepped off, arriving or staying, keeps them from boarding it again on their own until they move or it leaves). `keep()` saves a platform as the foot of its stairs in the corridor, never the platform itself.
- **`src/sights.ts`**: the album's places, the data to edit when adding one (`Sight`: `ground`, `pieces`, all its street `makeSightRoad` shows of it, `walk`); each, the two exits' maps included, has its own screen in **`src/sight-scenes.ts`**, laid out after the real place and the photos: a `Layout` in art px (`start`, the `exit` sign and `camera` hotspots, registered per place by `loadPlace`, `solids`, `lamps`, `lit`, the boxes of the picture shining through the night, `over`, the boxes lifted above the traveller, gates' roofs mostly, cut from what `draw` paints through `k.above`, its own shape without the ground round it (a scene painting nothing there lifts its boxes whole), `stands`, what is cut out of that layer and sorted with the traveller at its foot, trees by the path, `puffs`, smoke and spray) and a `draw` over the shared `kit` of painters, drawn by `makeScene` on first use. Start, sign and camera must stay connected on foot. A `Layout` may be larger than the screen (`width`, `height`: `mapWidth`, `mapHeight`, `scroll()`), and its solids come then from its paths (`trail`, `fenced`): Heian-jingu's garden, `Sight.garden` (`heian-garden`, the Shin-en, reached by the `way` signpost in the courtyard, a place of its own in `places`, `sightOf` naming its sight, `out` its exit back into it). A sight's street can be an `Avenue` (`avenues`, `dressRoad`): `heian-road` paints over `makeSightRoad`'s picture, keeping its road, stop and Uber spot (Nijo-dori), and runs on south, scrolling, down the Jingu-michi under the great torii to the Keiryu bridge, with a `photo` hotspot of its own. Each camera keeps a memory, its album page the place's id: `Sight.parts` adds such pages (Biwako's: `biwako-horai`, the Sky Bridge and Mt Horai, its `garden`, one long screen reached by the terrace's `way`, and `biwako-bridge`, the bridge's own camera there, `Layout.second`, hotspot `photo2`; `Layout.people` stands commuters' sprites still in a scene; `Sight.ropeway` puts **`src/ropeway.ts`**, `playRopeway`, a 320×200 picture on the flight's model, between its street, the foot station (`Piece` `ropeway`), and the summit, both ways, five minutes on the clock), `memoryPages` lists them, and `moved` in the import script sends those photos there. Reached from the `bus` hotspot in `town` (`Journey.trips`, `busStop`: a `busLines` bus naming its `en`, `Journey.busRide`: `makeBus` pulls up, `busLeaves` pulls away, modal set meanwhile; none once the trains stop, and not where the station is in its `walk`; a station with no trips has no stop at all, on the street or its area map) or on foot through the phone's Maps (`Journey.walks`, `walkTo`, out of doors only; `Phone.maps` over **`src/city-maps.ts`**, only the map `areaAround` the traveller (zoom: `Phone.zoom`, wheel, LT / RT, + / -), the `areas` in real lon/lat (`spots`: the stops shown; a stop added there joins the lines, drawn from `rail.ts`), a sight's `at` on one of them, checked at load: `walkFrom`, 12 min per km along the lines to whichever of its `walk` stations, +10, or bus stops, + their `foot` km, makes it shortest (each of its bus stops needs its `foot`, checked at load), or straight there × 1.3 where both ends have coordinates; only within the area; `outside` then moves to that station); bus and walk both arrive in the sight's own street, `<id>-road` (`roadTo`, `sightOfRoad`; `makeSightRoad` in `art.ts`, on `makeTown`'s layout: road, crossing, lights, stop, the Uber's spot; its surroundings from `pieces`; no passers-by yet): Maps also offers every station on the map (`spots`, straight there × 1.3), walked to its `town`, west exit. Every walk plays `walking` (a fade to the traveller on the way, the clock running on, the time added at the end). `entrance` goes in, the sight's `return` comes out, `bus` (where a bus serves it: `busesTo`) is `leaveSight`, a bus to any station of its lines, the timetable once they stop, `walkBack` the sign to the station. `pickup` is where Lorenzo's Uber comes: that road from a sight or its street (`lorenzo.at` holds it), else `nearestStation`. With no bus running the stop opens `Journey.timetable`, sheets from `makeTimetable` (`art.ts`), fictional minutes. **`src/bus-fare.ts`**: `BusFare`, the fare box by the driver at the end of a ride, on the vending machine's model with the shared `Purse`: any coins or note up to `busFare`, the change back in the tray (`makeChange`), no leaving unpaid unless the purse cannot cover it: then `busRide` leaves the traveller where they got on, dazed (`stun`). The two without `pieces` are the exits' maps. A sight's id must differ from every station's (checked at load). **`src/photo-book.ts`**: `PhotoBook`, the album, opened by the camera (`photo`, at that page) or the Journal, reading `photos/index.json`; `collected` holds the sight ids. A 480×320 picture like the pause menu's (`fitPicture`, `crispText`): an open book on a desk, the contents spread (`slot`), a spread per page (contact sheet, stamp, the mounted print) and the close-up, pages turned by `turn` (the leaf squeezed across the spine); the canvas has the screen's resolution (`fit`, `k` screen px a book px): the book is drawn in book pixels, unsmoothed, the photos smoothed over it (`photo`), shrunk once a session to that resolution (`shrink`, `prints`; the close-up is the photo itself, the last one kept). ## Conventions

- The first-person views (hall, gate, konbini) have no DOM header or footer: no title, clock, Back button, status or help bars outside the pixel art. Leaving is Esc / B (or walking away, in the hall); what the player needs goes into the picture itself.

- Player-facing game text and the docs (`README.md`, `REFERENCES.md`) are in **English**; immersive Japanese signage and announcements stay in Japanese. The kiosk is Japanese/English. Keep `README.md` and `REFERENCES.md` in sync when gameplay or sources change.
- The code is deliberately compact: dense one-line methods and inline styles. Match the surrounding density instead of reformatting.
- Fares follow the real operating km and JR's bands (`fares.ts`; the Kyoto km are rounded, the Shinkansen express charge simplified); timetables are decorative. A new local stop needs its km in `fromTokyo` or `fromKyoto` (a missing one throws at load). Platform numbers are fictional but must stay consistent everywhere: each station's `tracks` in `network.ts` must hold its routes' `platform` (checked at load; Tokyo's Tokaido Shinkansen 18/19, Kyoto's 11/12).
- Lines live only in `rail.ts`. The Tokyo fare map (`tokyo-fares.ts`) adds nothing but layout: where stations and bends go (`tokyoStations` x/y, the loop, `pins`), the `runs` of drawn track between them with the stations spread along, label sides, line plates (`lineLabels`) and `drawnVia` where a line does not take the shortest drawn way; `board()` routes every local line whose stops are all placed along that track and offsets lines sharing it side by side (same colour, same stroke). Everything drawn claims its box (`claim`, `taken`), and the 現在地 tag takes the free spot nearest its station, so a new label only has to claim its own. A new line or stop goes in `rail.ts` first, then gets a place on the board. `docs/tokyo-stations.md` lists the board's stations by line from `rail.ts`. The Kyoto side's board is the same drawing with its own `Layout` (`kyoto-fares.ts`: lake and rivers in `water`, `sights` for places without a stop of their own); `makeFareMap` picks the layout from the station.
