# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Yorimichi (寄り道) is a small top-down Japan travel-journal game prototype: Phaser 3 + TypeScript + Vite, with no external assets and no backend. `AGENTS.md` holds the repository guidelines (style, commits, PRs). Follow it as well.

## Commands

- `npm ci`: install (Node.js 22.12+).
- `npm run dev`: Vite dev server (binds `0.0.0.0`).
- `npm run build`: `tsc --noEmit` then `vite build` to `dist/`. This is the only automated check: there are no tests, linter, or formatter.
- `npm run preview`: serve `dist/`.
- `node scripts/subset-pixel-font.mjs <DotGothic16-Regular.ttf | PixelMplus10-Regular.ttf>`: regenerates `src/fonts/<font>-subset.woff2` from every character in `src/`: DotGothic16 is the kiosk's pixel font, PixelMplus10 the map signs' bitmap font. Re-run both after adding Japanese text; missing glyphs fall back to Noto Sans JP.
- `npm run build:mobile`: build, then `scripts/export-mobile.mjs` inlines the bundled JS and CSS into `dist/yorimichi-mobile.html` (optional output path argument: `node scripts/export-mobile.mjs <path>`). The script finds assets by regex-matching Vite's `<script type="module" crossorigin src=…>` and `<link rel="stylesheet" crossorigin href=…>` tags, so a change to how `index.html` loads assets can break it.

Verification is manual in the browser: movement (tap-to-walk and arrow keys), interaction prompts, ticket purchase and cancellation, platform validation, return trips, and the souvenir journal. For kiosk changes, check both the Japanese and English screens and that Escape closes the kiosk.

## Architecture

- **`src/main.ts`**: a single Phaser scene, `Journey`, on a fixed 960×640 canvas. `loadPlace(place)` tears down and rebuilds everything per location: the world container, HUD, collision rectangles (`solids`), commuters, and player. Interaction hotspots in `nearby()` and the collision rectangles are **hardcoded pixel coordinates** that must line up with what `art.ts` draws. Tap-to-walk uses a BFS over a 16px grid (`navigate`). In-game dialogs are Phaser containers stored in `this.modal`. Any non-null `modal` suspends movement and interaction.
- **`src/art.ts`**: all visuals are drawn procedurally into 480×320 canvas textures (`map-<place>`, `traveller-<dir>-<frame>`, `commuter-<look>-<dir>-<frame>`) and shown at 2× with `pixelArt: true`. So art coordinates × 2 = scene coordinates. The map and exit-pillar canvases are allocated at twice that size and drawn in art coordinates (`mapCanvas`), so their lettering (`letter`) can use the PixelMplus10 bitmap font, whose outlines are whole pixels: 10px small print (5 art px per line, half an art px per dot) or `big` at 20px (10 art px, a dot per art px). Kanji and kana are as wide as the line is high, Latin half that, and the signs are sized around it. Other sizes would blur the dots. The game only starts once that font is loaded; at the hubs the world container sits 24px lower (`this.world.y`) so the back wall has room for the station's name, and pointer and prompt positions convert through it. The gate signs show their tracks from `tracksFor()`. The hub map mirrors the first-person hall's layout (machine wall at the back, ticket office then central gates on the left, Shinkansen transfer gates on the right, or a NewDays where `hasShinkansen(hub)` is false); keep the two views consistent when either changes. The art-px landmarks are listed above `makeHub`, which draws a station's map (`map-<hub>`) and exit pillars the first time it is visited; the station's name plate grows to hold a long name. The board above the machines is a little fare map where `onTokyoBoard` (the Tokyo area), the lines through the station (`boardLines`) elsewhere; the halls (`hall-picture.ts`, `hall-scene.ts`, `hall-voxels.ts`) do the same.
- **`src/people.ts`**: the commuters' outfits (`looks`), shared by the hall's sprites (`hall-scene.ts`) and the top-down commuters (`art.ts`, animated in `main.ts`), so the same people appear in both views. `Figure` is a commuter as the concourse simulation in `main.ts` has them; the hall shows those figures live (the simulation keeps running under it), placed through `fromConcourse` in `hall-scene.ts`, a piecewise mapping of top-down scene pixels onto hall units anchored on landmarks both views share (office counters, gate lanes, the bank's pillars and machines, the Shinkansen gate lanes or the shop door, the exit pillars; `anchors(shinkansen)`). Moving any of these in either view means updating its anchors. The machine the player stands at (in front of it in the hall, or before it on the map) is `playerSpot`: commuters never pick it and those on the way there turn to another (`giveWay`); one already using it finishes first, and meanwhile the hall refuses it (`busy`). On the map, player and commuters jostle instead of colliding: contact slows both for a moment (`bump`) and nudges a walking player aside, one distance check per commuter.
- **`src/clock.ts`**: the journey's own clock (game ms, Japan time read through the UTC fields), `speed` × real time, advanced by `tick()` in `Journey.update` by the real time elapsed (`performance.now()`, not Phaser's delta, which stops in a hidden tab and is capped in a throttled one), so it runs under every overlay and in the background and saved as `clock` in the save; `?time=HH:MM` sets it at load, and `debugTime` (T, or a click on the HUD's clock) at any time through `setTimeOfDay`, retiming the platform's trains. The HUD's top left shows it (`day`, `clockText`, kept up in `update`); `clockBadge()` is the clock in the hall's and gate's headers. The stations open from `opens` to `closes`, trains are due from `firstTrain` to `lastTrain` (`trainsRun`, `inService`). On a platform a `Train`'s `due` is its departure in absolute game minutes: it pulls in `dwell` ms before it and never closes its doors earlier (`dueIn`); when the clock has run on without the scene (another tab or window), `runTrains` moves a late train's `due` on to the earliest it can still leave, with a minute's leeway; riding moves the clock on (`ride`: `localMinutes`, `shinkansenMinutes` in `fares.ts`). Night (`darkness`): out of doors (`outdoors()`) and at half strength on platforms, `Journey.shade`, a MULTIPLY render texture above the world, is filled dark blue and lightened by `lamps()` (scene px, matching `art.ts`); what glows by itself (`neon`: lit windows, shop signs) and, out of doors, the hotspot outlines sit in `over` above it; the HUD is at depth 10. Past `closes`, `closeStation()` sees the traveller out of the station (not while on a train); the street's `return` then offers to wait (`skipTo(opens)`) and `shutter` covers the entrance.
- **`src/rail.ts`**: the JR network as data, the single source of truth for lines: `railLines`, each with its colour, service and **ordered stops** (Japanese names; real lines and stopping orders, keeping only the stations the game knows; a rapid service simply omits the stations it skips; `loop` for the Yamanote Line). Its order is also the side-by-side order of lines on the fare map. `stopNames` gives every stop's English name (a stop without one throws at load), `linesAt(station)` gives the lines through a station, `firstLegs(from, to)` the lines to start on to reach `to` with the fewest changes (what a fare ticket's platform must be).
- **`src/network.ts`**: the single source of truth for places, stations, Shinkansen routes and platform numbers. Every stop of a local line of `rail.ts` is a station (`stations`, by id: its English name in kebab case, `stationAt(ja)`), all with the same concourse, corridor and platforms; `known` holds what sets a few apart (exit names, Tokyo's and Kyoto's track numbers, `maps` for an exit with its own map: Kamakura's east exit to `kamakura-trail`, Saga-Arashiyama's to `arashiyama`, `stationOf` the way back). Every other exit leads to the generic street `town`, drawn per station and exit on first use by `makeTown` in `art.ts`, its sign naming them (its area map, read up close, by `makeAreaMap`); `Journey.outside` remembers where the player came out, to walk back in there. A station without a Shinkansen platform gets the shop instead of the transfer gates and a local machine in place of the Shinkansen one (`machineKinds`). `tracks` numbers the two tracks of every line through a station (generated by `numberTracks` where `known` gives none: a pair per line, lines of one colour sharing it); `platformsAt(hub, service)` groups them into the platforms behind the gates (lines sharing a pair share one), and `tracksFor` gives the range shown on the gate signs, the gate's board and by the station staff (`駅員`). `routes` are the Shinkansen tickets, generated between every two stations of a Shinkansen line (`lineId`, from which they take their names and colour), from the track running the destination's way, priced by `shinkansenFare`; local trips are fare tickets. `boardLines` lists a station's lines for the board where it has no fare map. The traveller's home is `home` (Higashi-Nakano's west exit): that station's `town` gets a `lane` hotspot (the 東中野一丁目 sign drawn by `makeTown`'s `lane` flag) to `home-street` (`makeHomeStreet`, `homeStreetWidth` art px wide, scrolling sideways like the platform, drawn mirrored so that it starts on the right, where the street's left edge leads (lettering excepted, `homeLights`), its `home` hotspot on door 102), which leads into `apartment` (`makeApartment`, a 1LDK 480×416 art px scrolling vertically; its walls and furniture are `apartmentSolids`, its freestanding furniture `apartmentProps`, depth-sorted with the traveller; the `bed`'s `sleep()` in `main.ts` skips the clock to `wake`, 9:00); both keep `outside` set, and a new journey starts in the apartment. Adding a place usually needs the souvenir count and journal entries in `album` (`main.ts`), new map art in `art.ts`, and an exit in `known` leading there.
- **`src/fares.ts`**: fares as JR computes them: `fareBetween(from, to)` (Japanese names) is the March 2026 JR East band (`fareForKm`) for the shortest operating km along the local lines (Dijkstra over neighbouring stops, km from `fromTokyo` or `fromKyoto`, the real km in `between` where two neighbours are reached from opposite ways round); null between the Tokyo and Kyoto networks. `faresFrom` gives the amounts a station's machines sell. `tokyo-fares.ts` checks at load that it gives back the 30 transcribed fares of the Tokyo board. `shinkansenFare` adds the express charge to the fare for the Shinkansen km, `shinkansenMinutes` the ride's length for the machine's trains.
- **The corridor** (`corridor` place, `Journey.gateway` naming the hub and gates): where a gate's `pass` leads, drawn per hub and gates by `makeCorridor` in `art.ts` (layout in `corridorLayout`, art px). Each platform of `platformsAt` has a staircase on each side with its sign; the hotspots (`stairs<i>L`/`R`, and `return` at the gates) are registered into `hotspotFrames`/`hotspotShapes` when it loads. The world is taller than the screen when there are many lines: `mapHeight` bounds walking and the BFS grid, and `scroll()` moves `this.world.y` to follow the traveller (pointer and prompt positions already convert through it). Commuters walk it too (`corridorTrip`, the concourse's step queues between the stairs and the gate lanes, with the adjustment machine and staffed window as spots); their number is `corridorCrowd` (and `platformCrowd` on the platforms) for now, meant to become a per-station density. Climbing (`climb`) only checks that the punched ticket's trip starts at this hub, then goes up to the platform. The punched ticket is the one that went through, `punched` with the hub whose gate punched it (where its trip began). A platform's stairwell (`descend`) leads back down to the corridor at its stairs (`stairsSpot`), ticket still punched: changing lines is walking to another staircase. The way out is the gate view in exit mode (`exitGate`, `GateSide.exit`: the station's entrance hall drawn beyond, `entrance`; the gate never shows why it refuses), which refuses a ticket punched at the same station; the corridor's staffed window (`window` hotspot: the concourse's ticket office, `ticketOffice` in `art.ts`, drawn again set into the left wall beside the gates; `staffWindow`) cancels that entry and lets the traveller out whatever went wrong (the hook for charging a missing fare later): `fareDue` (`ticket-machine.ts`) checks the trip from the punch to here, and the gate keeps a ticket that covers it and refuses the rest. The fare adjustment machine (`adjust` hotspot in the corridor's last 40 px before the gates, opposite the staffed window; `MachineKind` `'adjust'` of the kiosk, tickets dragged from its wallet panel onto the card slot) swaps a short ticket for an `AdjustTicket` (精算券) once the difference is paid.
- **The Shinkansen** has no corridor: the transfer gates' `pass` goes straight to its ticket's track (`toPlatform`, from the route's `lineId` and `platform`), and a Shinkansen platform's stairwell (`descend`) opens the transfer gates in exit mode (`exitGate`), out to the concourse before them, which cancel an entry made there themselves (`GateSide.cancel`: the ticket comes back out unpunched); its line map offers the stations of its line (those on a local line), and `keep()` saves it as that concourse spot, dropping the ticket of a trip that ended there.
- **The platform** (`platform` place, `Journey.deck`: a `Deck` from `src/platform.ts`, the station, its `Platform` and the track the traveller came up on or arrives on): drawn per station and tracks by `makePlatform` in `art.ts`, `platformWidth` (two screens) long, scrolling sideways like the corridor vertically (`mapWidth`, `scroll()` moves `this.world.x` too; pointer and prompt positions convert through it) (layout in art px in its comment: tracks 44–88 and 232–276, a stairwell at each end, `downL`/`downR`, the route map board (`routeBoard`, `route` hotspot: `routeMap(track)` shows the face of the side the traveller stands on), the station sign in the middle on its own `<key>-sign` texture (`stationSign`), sorted with the people at its posts' feet, the shadows of the departure boards, which hang over the people: `platformBoards`, `makeBoard`, kept on top of the sorted world as `Journey.overhead`), trains by `makeTrain` per line (`trainLayout`, `doorMarks`: the doors line up with the 乗車位置 marks). `runOf(line, station, track)` gives where a track's trains go: the pair's first track towards the start of the line's `stops`, the second towards the end, both the only way at a terminus (so a route's `platform` must be the track running its way). Each track's `Train` cycles in `runTrains` (gap, arrive, alight, board, close, leave; lines sharing the platform take turns); commuters queue at the marks in two lines either side (`queues`, each commuter's place in `queue[2]`: even left, odd right, a row back every two; `slot`, `freeSlot`, `platformTrip`), get off through the middle in `alight` (`exitPoint`), then board in `boarding`, the lines taking turns (`served`) while `requeue` moves one line up. The traveller comes up at the end of the corridor stairs' side (`deck.track`) and boards from a queue (`door<track>-<k>` hotspots, outlined on the train's door itself, the glow kept above the people and trains, but not clickable: a click on a standing train picks its nearest door; `queueEnd`, `boardAt` boards on their own when nobody is ahead, `boardable`) and rides (`modal` set, hidden): on boarding, the doors held open, `lineMap` offers the stops `alightAt` knows (every station), and on a loop (`loopRing`) the ring, also on the route map; the choice (`train.to`) shuts the doors at once and, once the train has left, `toPlatform(train.to)` lands them on that station's platform as the train pulls in (`arriving`); staying steps back off by the same door (`stepOff`; `stayed`, the track of a train just stepped off, arriving or staying, keeps them from boarding it again on their own until they move or it leaves). `keep()` saves a platform as the foot of its stairs in the corridor, never the platform itself.
- **`src/ticket-machine.ts`**: the kiosk is a **DOM overlay**, not Phaser. It serves the three kinds of machine (`MachineKind`: `local`, `shinkansen`, and `charge`, which only asks for an IC card the player does not have). It is a step-based state machine (`Step`, with `history` for going back) and supports `ja`/`en` through `tr()`. It is scaled to a 960px design width with a `ResizeObserver`. It captures keyboard events (`stopPropagation`, Tab focus trap, Escape to close). It reports the purchased ticket through the `issue` callback. `main.ts` keeps the scene's `modal` set while the kiosk is open and resets the keyboard state when it closes. Screens are re-drawn from the JR West vending-machine guide; see `REFERENCES.md` for the sources and the deliberate adaptations.
- **`src/atm.ts`**: the konbini ATM opened by the `atm` hotspot in the street (`town`), a DOM overlay on the kiosk's model (`.machine-overlay` scaling, pixel skin, gamepad and keyboard, Escape) with its own steps (`Step`): transaction, card (dragged from the wallet panel onto `[data-slot="card"]`), PIN (on the memo), amount, fee, receipt, then the card and the cash taken from the outlets (card first). Foreign card: withdrawal and balance only. The account balance persists in `localStorage['yorimichi-bank']`; cash left in the outlet is credited back on `destroy`.
- **`src/phone.ts`**: the traveller's phone. `phone-mini` (drawn in `art.ts`) sits in the HUD's bottom right with an unread badge; a click, P or the pad's RB opens `Phone`, a DOM overlay (home screen, then the messaging app: conversations with Jennifer, Namiko and Lorenzo, `contacts`), with `modal` set as for the bag; the pad reaches it through `pad()`. Its state (`PhoneState`: chats, unread counts, Lorenzo's trip) is the save's `phone`. Lorenzo's trip runs in `Journey.lorenzo()` (each frame): `home` → `asked` (the suggested `askLorenzo` sent) → `flying` (his OK! after `phoneDue`) → `playFlight` (a 240×160 pixel map of East Asia, Hong Kong to Haneda, or to Kansai where `fareBetween` finds no fare to Tokyo) once no other overlay is open → `here`, at `nearestStation()` (`land`). His Uber (`uber-car-<k>`, its wheels turned by `roll` as it moves; `parkCar`) stands in that station's street (`town`, either exit) just past the crossing, solid and an `uber` hotspot once parked; it pulls up first when the traveller is in that street as he lands, and his message comes after. From `here`, `callLorenzo` calls him again: `called` → (already at `nearestStation()`: back to `here`) or `driving` (`at` cleared, his OK, 4 s) → `land` again, without the flight. The `uber` hotspot drives home (`uber`, `rideHome`: the clock on by `kmBetween` × 2.4 min, out at door 102 in `home-street` as the car drives off; Lorenzo then `here` at `home.hub`), except from the Kyoto side, where `kmBetween` finds no way.
- **`src/wallet.ts`**: the player's purse (yen coins and notes), its pixel-art pieces, change-making (fewest pieces), the walk slowdown from carrying coins (`walkFactor`), and the synthesized machine sounds. The kiosk always shows its payment block (slots under the screen, ticket and change outlets) and the wallet beside it; pieces are dragged onto `[data-slot]` elements or clicked. ¥1 and ¥5 coins are refused into the change outlet.
- **`src/machine-hall.ts`** and **`src/hall-scene.ts`**: the first-person ticket hall before the kiosk. `machine-hall.ts` is a DOM overlay holding the controls (strafe, look, gamepad, hover/click on machines, enlarged map); every machine of the bank, the charge-only ones included, opens the kiosk. `hall-scene.ts` renders the room with three.js into a canvas at about 640px wide, scaled up with `image-rendering: pixelated`; textures are painted procedurally. The Tokyo fare map is the crisp SVG in a `CSS3DRenderer` layer behind the canvas, seen through a transparent hole the WebGL plane punches (so nearer meshes still occlude it); the machine signs use the same technique, and the payment faces are pixel-art canvases (2 world px per texel) in that same CSS3D layer, and the camera reproduces the former CSS framing (pivot with the eye 1000px behind). Machine picking uses a raycaster on the same camera.
- **`src/hall-picture.ts`**: the default view of the ticket hall, a 400×250 pixel-art picture (`HallPicture`), repainted when its eye walks along the bank (x from `MachineHall`) or pans up to the board (pitch above 10°), with the same interface as `HallScene` (`render`, `pick`, `setHover`, `dispose`), drawn with the gate's exported `Picture` from the layout constants and painters `hall-scene.ts` exports; the Tokyo fare map is the SVG laid over its board. `MachineHall` takes a `pixel` flag: the arrows, D-pad and stick then walk from machine to machine (held, they keep going; a click on a far machine walks there, a second one uses it), ↑ / ↓ to the board and back, instead of strafing and looking. `main.ts` picks it unless the URL has `?hall=3d` (the three.js hall) or `?hall=voxel` (below).
- **`src/hall-voxels.ts`**: `HallVoxels`, the same hall and first-person camera as `HallScene`, built of lit, shadowed voxels: `Blocks` gathers scaled, coloured cubes into one `InstancedMesh` (bitmap lettering and canvases are raised a voxel per pixel), each machine is its own mesh for picking, and each commuter is carved from their sprite frames (`personBlocks`, front/back × profile). The Tokyo fare map is the CSS3D SVG behind a hole, as in `HallScene`. Its layout repeats `HallScene`'s (exported constants), so moving a landmark means updating both.
- **`src/ticket-gate.ts`**: the first-person ticket gate opened by the `local`/`shinkansen` hotspots: a DOM overlay (reusing the hall's `.machine-hall` header and footer) with an inventory panel and a 240×150 pixel-art picture scaled up whole: `Picture` projects flat world polygons and fills them pixel by pixel (no anti-aliasing), two fixed `views` (before the gate, over the exit slot) swapped through a dithered fade, repainted only when its key changes. The ticket is dragged from the inventory onto the slot (hit-tested against the rectangles last drawn). `main.ts` passes a `refuse(ticket)` check (empty string when valid) and gets `pass` (then the corridor, or out after the exit gate) or `leave`; in exit mode the gate keeps every ticket it lets through. It never sends the player to the machines: getting a ticket is up to them. It reuses `box` and `pixelText` exported from `hall-scene.ts`. A ticket the gate lets through gets `punched` (drawn as a hole by `paintTicket`). **`src/inventory.ts`** is the bag opened from the top band (or X): the same ticket drawings and wallet, read-only.
- **State**: the tickets (`Journey.tickets`, several at once; each purchase adds one) persist through **`src/save.ts`**, a versioned save in `localStorage['yorimichi-save']` meant to hold the progress too: add fields to `Save`, and bump `version` when old saves cannot be read. It also holds where the traveller stands (`Spot`: place, position, `outside` and, in a corridor, its gates), restored by `create`. `Journey.keep()` writes it on each purchase, when boarding uses up the ticket that went through the gate (`useTicket`; a gate's punch is saved only with the traveller in the corridor behind it, so a reload anywhere else gives the ticket back unpunched), on each `loadPlace`, at most once a second while walking and on stopping, and when the page is hidden. Shinkansen tickets are one-way; an exit's own map (the Kamakura trail, the bamboo path) walks back into its station via the `return` hotspot. Souvenirs persist in `localStorage['yorimichi-memories']`. The wallet persists in `localStorage['yorimichi-wallet']` and is shared by reference between `Journey` and the kiosk; pieces inserted go to the change outlet when the kiosk is destroyed. Each machine's outlets (ticket included) persist per hub and machine id in `localStorage['yorimichi-trays']` until taken.

## Conventions

- Player-facing game text and the docs (`README.md`, `REFERENCES.md`) are in **English**; immersive Japanese signage and announcements stay in Japanese. The kiosk is Japanese/English. Keep `README.md` and `REFERENCES.md` in sync when gameplay or sources change.
- The code is deliberately compact: dense one-line methods and inline styles. Match the surrounding density instead of reformatting.
- Fares follow the real operating km and JR's bands (`fares.ts`; the Kyoto km are rounded, the Shinkansen express charge simplified); timetables are decorative. A new local stop needs its km in `fromTokyo` or `fromKyoto` (a missing one throws at load). Platform numbers are fictional but must stay consistent everywhere: each station's `tracks` in `network.ts` must hold its routes' `platform` (checked at load; Tokyo's Tokaido Shinkansen 18/19, Kyoto's 11/12).
- Lines live only in `rail.ts`. The Tokyo fare map (`tokyo-fares.ts`) adds nothing but layout: where stations and bends go (`tokyoStations` x/y, the loop, `pins`), the `runs` of drawn track between them with the stations spread along, label sides, line plates (`lineLabels`) and `drawnVia` where a line does not take the shortest drawn way; `board()` routes every local line whose stops are all placed along that track and offsets lines sharing it side by side (same colour, same stroke). A new line or stop goes in `rail.ts` first, then gets a place on the board. `docs/tokyo-stations.md` lists the board's stations by line from `rail.ts`.
