# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Yorimichi (寄り道) is a small top-down Japan travel-journal game prototype: Phaser 3 + TypeScript + Vite, with no external assets and no backend. `AGENTS.md` holds the repository guidelines (style, commits, PRs). Follow it as well.

## Commands

- `npm ci`: install (Node.js 22.12+).
- `npm run dev`: Vite dev server (binds `0.0.0.0`).
- `npm run build`: `tsc --noEmit` then `vite build` to `dist/`. This is the only automated check: there are no tests, linter, or formatter.
- `npm run preview`: serve `dist/`.
- `node scripts/subset-pixel-font.mjs <DotGothic16-Regular.ttf>`: regenerates `src/fonts/DotGothic16-subset.woff2` (the kiosk pixel font) from every character in `src/`. Re-run it after adding Japanese text to the kiosk; missing glyphs fall back to Noto Sans JP.
- `npm run build:mobile`: build, then `scripts/export-mobile.mjs` inlines the bundled JS and CSS into `dist/yorimichi-mobile.html` (optional output path argument: `node scripts/export-mobile.mjs <path>`). The script finds assets by regex-matching Vite's `<script type="module" crossorigin src=…>` and `<link rel="stylesheet" crossorigin href=…>` tags, so a change to how `index.html` loads assets can break it.

Verification is manual in the browser: movement (tap-to-walk and arrow keys), interaction prompts, ticket purchase and cancellation, platform validation, return trips, and the souvenir journal. For kiosk changes, check both the Japanese and English screens and that Escape closes the kiosk.

## Architecture

- **`src/main.ts`**: a single Phaser scene, `Journey`, on a fixed 960×640 canvas. `loadPlace(place)` tears down and rebuilds everything per location: the world container, HUD, collision rectangles (`solids`), commuters, and player. Interaction hotspots in `nearby()` and the collision rectangles are **hardcoded pixel coordinates** that must line up with what `art.ts` draws. Tap-to-walk uses a BFS over a 16px grid (`navigate`). In-game dialogs are Phaser containers stored in `this.modal`. Any non-null `modal` suspends movement and interaction.
- **`src/art.ts`**: all visuals are drawn procedurally into 480×320 canvas textures (`map-<place>`, `traveller-<dir>-<frame>`, `commuter-<look>-<dir>-<frame>`) and shown at 2× with `pixelArt: true`. So art coordinates × 2 = scene coordinates. The map and exit-pillar canvases are allocated at twice that size and drawn in art coordinates (`mapCanvas`), so their lettering (`letter`, anti-aliasing thresholded away) is crisp at screen resolution; at the hubs the world container sits 24px lower (`this.world.y`) so the back wall has room for the station's name, and pointer and prompt positions convert through it. Platform signage is drawn from `platformFor()`. The hub map mirrors the first-person hall's layout (machine wall at the back, central gates on the left, ticket office and Shinkansen gates on the right); keep the two views consistent when either changes.
- **`src/people.ts`**: the commuters' outfits (`looks`), shared by the hall's sprites (`hall-scene.ts`) and the top-down commuters (`art.ts`, animated in `main.ts`), so the same people appear in both views. `Figure` is a commuter as the concourse simulation in `main.ts` has them; the hall shows those figures live (the simulation keeps running under it), placed through `fromConcourse` in `hall-scene.ts`, a piecewise mapping of top-down scene pixels onto hall units anchored on landmarks both views share (gate lanes, the bank's pillars and machines, office counters, Shinkansen gates, the exit pillars). Moving any of these in either view means updating its anchors. The machine the player stands at (in front of it in the hall, or before it on the map) is `playerSpot`: commuters never pick it and those on the way there turn to another (`giveWay`); one already using it finishes first, and meanwhile the hall refuses it (`busy`). On the map, player and commuters jostle instead of colliding: contact slows both for a moment (`bump`) and nudges a walking player aside, one distance check per commuter.
- **`src/network.ts`**: the single source of truth for places, hubs (`tokyo`, `kyoto`), routes, fares, and platform numbers. `platformFor(hub, service)` keeps the station signs, kiosk, ticket, and station staff (`駅員`) consistent. Adding a route or place usually also needs changes in `main.ts` (decoy and correct train names in `interact`, `returnHub`, the souvenir count and journal entries in `album`) and new map art in `art.ts`.
- **`src/ticket-machine.ts`**: the kiosk is a **DOM overlay**, not Phaser. It is a step-based state machine (`Step`, with `history` for going back) and supports `ja`/`en` through `tr()`. It is scaled to a 960px design width with a `ResizeObserver`. It captures keyboard events (`stopPropagation`, Tab focus trap, Escape to close). It reports the purchased ticket through the `issue` callback. `main.ts` keeps the scene's `modal` set while the kiosk is open and resets the keyboard state when it closes. Screens are re-drawn from the JR West vending-machine guide; see `REFERENCES.md` for the sources and the deliberate adaptations.
- **`src/wallet.ts`**: the player's purse (yen coins and notes), its pixel-art pieces, change-making (fewest pieces), the walk slowdown from carrying coins (`walkFactor`), and the synthesized machine sounds. The kiosk always shows its payment block (slots under the screen, ticket and change outlets) and the wallet beside it; pieces are dragged onto `[data-slot]` elements or clicked. ¥1 and ¥5 coins are refused into the change outlet.
- **`src/machine-hall.ts`** and **`src/hall-scene.ts`**: the first-person ticket hall before the kiosk. `machine-hall.ts` is a DOM overlay holding the controls (strafe, look, gamepad, hover/click on machines, IC charge notice, enlarged map). `hall-scene.ts` renders the room with three.js into a canvas at about 640px wide, scaled up with `image-rendering: pixelated`; textures are painted procedurally. The Tokyo fare map is the crisp SVG in a `CSS3DRenderer` layer behind the canvas, seen through a transparent hole the WebGL plane punches (so nearer meshes still occlude it); the machine signs use the same technique, and the payment faces are pixel-art canvases (2 world px per texel) in that same CSS3D layer, and the camera reproduces the former CSS framing (pivot with the eye 1000px behind). Machine picking uses a raycaster on the same camera.
- **State**: the active ticket lives only in memory (`Journey.ticket`). It is consumed when the player boards. Shinkansen tickets are one-way, and local excursions return to their hub via the `return` hotspot. Souvenirs persist in `localStorage['yorimichi-memories']`. The wallet persists in `localStorage['yorimichi-wallet']` and is shared by reference between `Journey` and the kiosk; pieces inserted go to the change outlet when the kiosk is destroyed. Each machine's outlets (ticket included) persist per hub and machine id in `localStorage['yorimichi-trays']` until taken.

## Conventions

- Player-facing game text and the docs (`README.md`, `REFERENCES.md`) are in **English**; immersive Japanese signage and announcements stay in Japanese. The kiosk is Japanese/English. Keep `README.md` and `REFERENCES.md` in sync when gameplay or sources change.
- The code is deliberately compact: dense one-line methods and inline styles. Match the surrounding density instead of reformatting.
- Fares are fictional and timetables are decorative. Platform numbers are fictional but must stay consistent everywhere (Tokyo 3/19, Kyoto 33/11).
